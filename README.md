## Создание базового интерфейса

Создание базового интерфейса, состоящего из трех страниц:

### Первая страница
Для просмотра списка услуг (отели, товары, рейсы и тд) в виде карточек (плиткой в 2-4 столбца) с:
- наименованием
- ценой (датой рейса, мощностью устройства и т.д.)
- картинкой
- отдельным элементом-карточкой текущей заявки (корзина) с указанием количества услуг в ней

> Количество вычисляется в контроллере-обработчике

### Вторая страница
При клике по карточке происходит переход на вторую страницу с подробной информацией об услуге:
- даты
- описание
- и т.д.

### Третья страница
При нажатии на текущую заявку по ее id открывается страница просмотра состава заявки:
- поля самой заявки
- каждая ее услуга отображается ниже отдельной карточкой друг под другом
- поля услуги вывести слева направо в 1 строку
- справа для каждой из них поле м-м (количества/порядка/главный/комментарий/другое), которое в последующих лабораторных сможет менять пользователь
- в заявке или в еще одном поле м-м должно быть поле результата вычислений (пока указано готовое значение)

---

## Header приложения

В header приложения добавить:

- кнопку/иконку **Домой** — для навигации на страницу услуг
- поле **input** для фильтрации на сервере списка услуг по одному из полей:
  - наименование
  - цена
  - дата события

> Поле поиска должно сохраняться после запроса

---

## Технические требования

- Всего в приложении должно быть **3 GET запроса** и **две модели-коллекции**
- Все данные для обеих страниц нужно брать прямо из двух коллекций (массива услуг и словаря заявки), **без использования БД**
- Никаких массивов внутри отдельной услуги (соблюдать атомарность и 1НФ), но можно и нужно писать большие текстовые описания
- Никакого редактирования, только поиск и просмотр
- **Без JavaScript**

---

## Стили и изображения

В приложении должны быть использованы стили:

- для каждого элемента списка подгружается свое изображение
- изображения услуг отображаются на всех трех страницах
- изображения хранятся в Minio
- наименование изображения указано ключом на латинице, хранится в модели отдельным полем
- разработать стиль приложения, который будет применяться далее в последующих лабораторных по фронтенду
- **CSS вынести в отдельный файл**
